# Agent baseline protocol

## Purpose

The main manuscript comparison is designed to quantify the value of the **complete PUR-NEW decision strategy**, not to make the headline baseline nearly as sophisticated as the proposed system.

The primary baseline is therefore intentionally simple but scientifically legitimate.

## Headline baseline: `naive_direct_llm`

The baseline represents a natural unguided use case:

> give a general-purpose LLM the original local experimental data and the finite candidate compositions, then ask it to choose a validation formulation.

It receives:

```text
original E1-E5 formulation information
raw original temperature measurements
raw original thermal-hold measurements
candidate IDs and candidate compositions
experimental task
```

It does not receive:

```text
state-aware model summary
master-curve conclusion
one-point calibration conclusion
external literature/database evidence
candidate-space evidence rationale
scientific Action catalog
precomputed Action outputs
candidate support scores
Pareto/robustness diagnostics
Planner
Skeptic
follow-up formulation identity
follow-up wet-lab outcome
controller-side benchmark target
```

The baseline is generated by `scripts/build_naive_baseline_view.py` and executed by `scripts/run_naive_llm_baseline.py`.

## Why this is the main baseline

The proposed Agent claims value from the combination of:

```text
state-aware physical/model findings
+ evidence retrieval
+ deterministic scientific Actions
+ process-state uncertainty
+ candidate-space scientific constraints
+ planning
+ scientific critique
+ frozen experimental criterion
```

If those same ingredients are pre-supplied to the headline baseline, the comparison no longer measures the value of the complete strategy.

The main-text comparison is therefore:

```text
naive direct LLM
versus
full PUR-NEW discovery-to-experiment Agent
```

This is an information-and-strategy ladder, and it must be described as such.

## What is not allowed

The simple baseline must not be made artificially nonsensical. It must not:

- receive false measurements;
- receive misleading candidate labels;
- be instructed to choose randomly;
- be denied the actual candidate compositions;
- be given a deliberately bad model when the Agent uses a stronger one;
- receive the hidden validation result;
- silently discard failed or abstaining runs.

The intended weakness is **lack of the proposed scientific strategy**, not sabotage.

## Supplementary strong controls

Evidence-rich controls remain useful, but they are not the headline comparison.

### `single_pass_tool_context`

Receives state-aware/action evidence in one pass but lacks the full discovery-to-experiment workflow.

### `deterministic_evidence_ranker`

Uses hand-coded evidence-support logic without an LLM.

### Optional V3 ablations

Remove one strategy component such as the state-aware Action, deterministic robustness layer or Skeptic.

These controls answer reviewer questions about whether the observed gain is due only to extra information or a manually encoded prior.

## Reporting order

Recommended main-text order:

```text
1. naive direct LLM
2. full Agent
3. physical wet-lab adjudication
```

Recommended supplementary order:

```text
1. deterministic evidence ranker
2. single-pass tool-context control
3. selected V3 ablations
```

## Claim boundary

A large improvement over `naive_direct_llm` supports the claim that the **complete PUR-NEW strategy** adds practical decision value.

It does not by itself prove that the multi-stage architecture alone is responsible, because the information budgets differ by design. Strong supplementary controls are used to test that narrower question.
